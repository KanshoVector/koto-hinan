このデータについて

何をする物か: 地図をタップ（または現在地）すると、国土地理院のデータで洪水に対応する最寄りの指定緊急避難場所、道路沿いの徒歩の分（1.0 m/s と 0.5 m/s）、その地点の想定浸水深を出します。洪水に対応しない場所の方が近い時はそれも出します。区全体の集計（論文の数と図）は同じ処理から出しています（build.py・out/stats.json・figs/）。押した点や現在地の座標はどこにも送らず、URL にも書きません。地図と浸水深の画像は、見ている範囲の分を配信元から取ります。

既存の道具（2022 年の「江東区の近い避難所を上位 15 件出す」道具）との差は 3 つ:
1. 洪水への対応のフラグ（国土地理院の disaster1）で絞り、洪水の指定が無い近い場所は「洪水の指定がありません」と出す。
2. 距離は直線でなく OpenStreetMap の道路沿いで、徒歩の分を 1.0 m/s と 0.5 m/s の 2 通りで出す。
3. タップした地点の想定浸水深（洪水・想定最大規模）を、公式の凡例の階級で出す。

経路が川を渡るか: 経路の 1 辺が OpenStreetMap の川の水域（water=river・waterway=riverbank）を 10 m 以上通る時に「渡る」とする。名前は水域の名前、無ければ渡る所に一番近い名前つきの中心線（waterway=river・300 m 以内）の名前。名前の分からない水域は「名前の分からない水路」と数で出す。水域の書き方の欠けや、運河を川として書いた所の影響を受ける。洪水の時に橋を渡れるかは見ていない。押した所が水域の中なら「川や海の上です」と出す。

作りの理由（v2・開発の記録）
  • サーバを置かない: 経路は build.py が事前に計算した「洪水に対応する場所を起点にした最短経路の木」（各節点の親）を route.json に書き出し、ブラウザは押した点に近い格子点から親を辿って線を描くだけにした。経路探索のサーバも外部の経路 API も使わないので、運用の費用と止まる所が無い。
  • 背景地図の選択（SPEC の設計の決定 3）: MapLibre GL JS 5.21.0 と OpenFreeMap のベクトル地図（明るい表示は positron、夜は dark）。鍵は要らない。地名は日本語を先に出し、漢字とかなは端末の書体で描く。浸水深は公式のラスタタイルを地名の下・道路の上に重ね、経路の線と点はその上に描く。Leaflet と OpenStreetMap のラスタは、文字が粗く古い見た目になるので替えた。

再現の手順: uv run --script build.py（取得は data/raw/ に保存し、2 回目からはそこから読む）→ uv run --script check.py（不変条件の検査）。地域は REGION=東京都江東区 のように替える。4 地域は OFFLINE=1 cmp/run_all.sh。この頁は cd site && python3 -m http.server で開く。

限界:

  • 指定緊急避難場所は国土地理院に登録された物だけ。江東区・墨田区・葛飾区は地理院の公開一覧で「指定避難所データのみ公開」で、区内は 0 件になる（区が指定していないという意味ではない）。収容人数・開設の状況・混雑・備考の条件（例「洪水は２階以上が対象」）は計算に入れていない。
  • 区外の場所は、その市区町村が指定した場所。経路が渡る川は上の決め方で全部出すが、洪水の時に橋を渡れるかは見ていない。
  • 円と道路網の比べ方: 「円が何 % 多いか」を道路網で届く人数で割ると、届く人数が少ない地域で値が大きく膨らむ（例 数千 %）。地域どうしの比較には、差を区の人口で割った値（stats.json の circle_minus_network_pct_of_ward）を使う。円が道路網以上になるのは作りの上で必ず成り立つ（道路距離は直線距離を下回らない）ので、それ自体は発見ではない。検査の「道路距離が直線より短い点 0」も経路の正しさの証拠にはならない。
  • 道路への寄せ方: 格子点と避難場所は、最寄りの道路の節点（交差点）へ直線で寄せる（線分上の最寄りではない）。その直線が川・線路・高速道路を横切るかは見ていないので、到達を甘く見る向きに働く（寄せた距離の最大は stats.json の snap_m）。
  • 浸水深の凡例は国土地理院のままで、基準の違う 2 つの区分の色が混ざっている（0.3m未満と0.5m未満、0.5〜1mと0.5〜3m は重なる階級）。結果の欄にはその市区の格子にある階級だけを出す。家の目安（0.5 m＝1 階の床・3 m＝2 階の床下・5 m＝2 階が水没）は国土地理院の浸水ナビの説明から。「着色なし」は想定区域外・タイルの未配信・0.1 m 未満（東京都の図面の規則）を区別できない。表示する値はタップ点に近い 50 m 格子点の 1 画素で、浸水域の境目では地図の色と違うことがある。
  • 届かない人の割合は、閾値と場所の集合に強く左右される（stats.json の E3 の sensitivity_unreached_pct と、市区内の場所だけの値 ward_sites_only を並べて読む）。0.5 m/s×20 分と 1.0 m/s×10 分は同じ 600 m で、感度の 6 通りは距離では 5 通り。
  • 人口は 2020 年国勢調査の 250m メッシュを 50 m 格子へ面積で按分した（MAUP: メッシュの切り方で分布が変わる。川や運河の上にも人が配られる）。区内は N03 の境界の内の点で数える（住所で数えると 1 件ずれる地域がある）。論文の数は stats.json から取る（この頁の距離は整数 m に丸めてある）。
  • OpenStreetMap の歩道・通路の記載の欠け、浸水した道路を歩けるか、坂・階段・夜間・混雑は見ていない。
